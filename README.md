# ระบบดึงยอดคำสั่งซื้อ

ดึงคำสั่งซื้อจาก **หลังบ้านร้านค้าของเราเอง** บน Lazada / TikTok Shop / Shopee ทุกเช้า
→ สกรีนจับคู่รุ่นสินค้า → ขึ้น Postgres → ส่งอีเมลสรุปให้ทีม + Dashboard ดูว่าร้านไหนติดตรงไหน

**เปิดใช้อยู่ 18 ร้าน** — Shopee 10 · TikTok 6 · Lazada 2
(ใน `shops.yaml` มี 35 ร้าน อีก 17 ร้านตั้ง `enabled: false` ไว้ ส่วนใหญ่คือร้าน Official OSUKA ที่รอล็อกอิน)

ต่างจาก `pdp-scraper` ที่เก็บสเปกสินค้าในตลาด — ตัวนี้เก็บ **ออเดอร์ของร้านเราเอง**

> **ใช้งานจริงทุกวันแล้ว** ดึงข้อมูลจริงจากหลังบ้านด้วย Playwright ครบทุกร้าน
> ไม่ได้ใช้ข้อมูลปลอมแล้ว (`MockAdapter` เหลือไว้ใช้ในเทสต์เท่านั้น)
> ดู [CLAUDE.md](CLAUDE.md) สำหรับสถานะแต่ละเฟสและข้อควรระวังตอนแก้โค้ด

## ติดตั้ง (ครั้งเดียว)

```powershell
.\setup.ps1
```

ต้องมี Python 3.11 ขึ้นไป สคริปต์จะสร้าง `.venv` + ลงไลบรารี + สร้าง `.env` ให้

## ใช้งาน

```powershell
.\run_daily.ps1                     # ดึงทุกร้าน (ข้อมูลของ "เมื่อวาน")
```

```powershell
.\run_daily.ps1 -Shop lazada_01     # ดึงร้านเดียว
```

```powershell
.\run_daily.ps1 -Date 2026-08-01    # ระบุวันที่ของรอบเอง
```

ธงอื่นของ `run_daily.ps1`: `-Platform` · `-SkipIfDone` · `-SkipPreflight` (ข้ามขั้นตรวจ
ความพร้อม ใช้ตอนดึงร้านเดียวซ้ำ ๆ) · `-SkipScreen` (เอาไฟล์ดิบอย่างเดียว) · `-Mail`

**exit code ของ `run`** — `0` = ครบทุกร้าน · `1` = มีร้าน FAILED · `2` = มีรอบอื่นรันอยู่

คำสั่งย่อย:

```powershell
.\.venv\Scripts\python.exe -m src.cli health
```

```powershell
.\.venv\Scripts\python.exe -m src.cli login --shop shopee_01
```

```powershell
.\.venv\Scripts\python.exe -m src.cli backfill --from 2026-07-01 --to 2026-07-31
```

มีครบ: `run` · `backfill` · `login` · `health` · `dashboard` · `notify` · `reminders`

## ตั้งค่า

### `config/shops.yaml` — รายชื่อร้าน

```yaml
- shop_id: lazada_01
  platform: lazada
  adapter: playwright    # mock | playwright | api
  display_name: "ชื่อร้าน"
  profile_key: lazada_01 # ร้านที่ใช้บัญชีเดียวกันใส่ค่าเดียวกัน = ล็อกอินครั้งเดียวพอ
  enabled: true
```

⚠️ **`display_name` ต้องตรงกับชื่อจริงบนหลังบ้านเป๊ะ ๆ** เพราะใช้จับคู่แถวร้าน
บนหน้า `/portal/shop` ของ Shopee ตอนสลับร้าน ถ้าไม่ตรงจะกดผิดร้านโดยไม่มีอะไรเตือน

**ร้านที่ยังดึงไม่ได้** ให้ปิดไว้แบบนี้ จะขึ้นสีเทา (ข้าม) ไม่ใช่สีแดง (พัง):

```yaml
  enabled: false
  skip_reason: "บัญชีมีสิทธิ์แค่จัดการโฆษณา — รอเจ้าของเพิ่มสิทธิ์"
```

### `config/brands.yaml` — จับกลุ่มร้านเป็นแบรนด์

ร้านเดียวกันขายหลายแพลตฟอร์มแต่สะกดชื่อไม่เหมือนกัน จับกลุ่มอัตโนมัติด้วยชื่อจึงพลาดได้
ไฟล์นี้จึงประกาศไว้ให้ชัด **ห้ามเดาเองว่าร้านไหนเป็นแบรนด์เดียวกัน**
ต้องได้รับการยืนยันจากเจ้าของงาน — ถ้ารวมผิด ยอดขายคนละร้านจะถูกบวกรวมกันเงียบ ๆ

### `config/settings.yaml` — ที่แก้บ่อย

| ค่า | ตอนนี้ | ความหมาย |
|---|---|---|
| `fetch.lookback_days` | `1` | ดึงย้อนหลังกี่วัน — `1` = วันต่อวัน |
| `fetch.refresh_status_days` | `0` | ไล่อัปเดตไฟล์ย้อนหลังกี่วัน — ตั้ง `7` เมื่ออยากให้ออเดอร์ที่ถูกยกเลิกทีหลังอัปเดตตาม |
| `privacy.include_pii` | `false` | `true` = เก็บชื่อผู้ซื้อเต็มลง Excel |
| `rate_limit.delay_between_shops` | `[3, 7]` | หน่วงระหว่างร้าน (วินาที) **ต่ำกว่า 3 ไม่ได้** |
| `rate_limit.shop_timeout_sec` | `600` | ร้านหนึ่งใช้เวลาได้นานสุดเท่าไร |

### ข้อมูลส่วนบุคคล (PDPA)

ค่าเริ่มต้น `include_pii: false` หมายถึง Excel จะได้:

- `buyer_username` → mask เป็น `s*****i`
- `province` → **เก็บไว้** (วิเคราะห์ได้โดยไม่ระบุตัวตน)
- ชื่อ-นามสกุล / เบอร์โทร / ที่อยู่ / เลขบัตรประชาชน → **ไม่เขียนลงไฟล์เลย**

ไฟล์ดิบใน `data/raw/` ยังเก็บของเดิมไว้ debug และอยู่ใน `.gitignore` แล้ว

## กฎเหล็ก

1. **ห้ามสร้างตัวเลขขึ้นเอง** — ไม่มีข้อมูล = `"Null"` + เขียนเหตุผลลง `notes`
2. **`order_id` / `sku` / `tracking_no` เป็น string เสมอ** และ Excel ต้องบังคับ
   `number_format = "@"` — เลข 19 หลักของ TikTok ถ้าหลุดเป็น int จะโดนปัดหลักท้ายทิ้ง
3. **ห้าม commit** `.env` · `data/sessions/` · `output/` · `*.db`
   `data/sessions/` คือ cookie หลังบ้าน หลุดแล้วคนอื่นเข้าจัดการร้านได้เลย **ห้าม `git add -f`**
4. **ห้ามพยายามผ่าน CAPTCHA / OTP / 2FA** — เจอเมื่อไหร่ให้หยุดร้านนั้น รายงาน `AUTH_REQUIRED`
5. **ห้ามปิด Chrome ด้วย `Stop-Process -Force`** — cookie ที่ยังอยู่ในหน่วยความจำจะไม่ถูก
   เขียนลงดิสก์ การล็อกอินที่เพิ่งทำหายทั้งดุ้น ต้องปิดผ่าน `adapter.close()` เสมอ
6. **`.ps1` ต้องเซฟเป็น UTF-8 *with BOM*** (ดูหัวข้อแก้ปัญหาข้างล่าง)
7. **ระบบไม่เก็บ ไม่อ่าน ไม่พิมพ์รหัสผ่าน** ที่ไหนเลย — คนล็อกอินเองครั้งเดียวต่อร้าน

## สถานะการดึง

| status | สี | หมายความว่า |
|---|---|---|
| `SUCCESS` | 🟢 | ครบ |
| `PARTIAL` | 🟡 | ได้ไฟล์แต่ไม่สมบูรณ์ — ตอนนี้ใช้กับ `EMPTY_RESULT` |
| `FAILED` | 🔴 | **ต้องลงมือแก้** |
| `SKIPPED` | ⚪ | ปิดไว้เองใน `shops.yaml` ไม่ใช่ความพัง |
| `RUNNING` | 🔵 | กำลังทำงาน — ค้างเกิน 60 นาทีจะถูกเปลี่ยนเป็น FAILED |

**"ไม่มีออเดอร์วันนั้น" = `PARTIAL` ไม่ใช่ `FAILED`** — ร้านเล็กมีสิทธิ์ขายไม่ได้เลยสักชิ้น
ถ้าทำเป็นสีแดง สีแดงจะเฝือจนมองข้ามร้านที่พังจริง

**`error_type` ที่ห้าม retry:** `AUTH_EXPIRED` / `AUTH_REQUIRED` / `NO_PERMISSION`
ยิงซ้ำก็ไม่ผ่าน มีแต่เสี่ยงโดนล็อกบัญชี
retry ได้เฉพาะ `RATE_LIMITED` / `TIMEOUT` / `NETWORK` (backoff 2s → 8s → 30s)

## แก้ปัญหาที่เจอบ่อย

**ร้านขึ้น `AUTH_EXPIRED`**
cookie หมดอายุ ต้องล็อกอินร้านนั้นใหม่:

```powershell
.\.venv\Scripts\python.exe scripts\login_save.py --shop shopee_01
```

หน้าต่างจะเปิดขึ้นมาให้ล็อกอินเอง แล้วรอจนเจอ cookie **ตัวใหม่จริง** ค่อยเซฟและปิดเอง
ล็อกอินเสร็จไม่ต้องกดปิด — ถ้าจะปิดเองให้กด **X** อย่าใช้ Task Manager

**ร้านขึ้น `NO_PERMISSION`**
บัญชีที่ล็อกอินมีสิทธิ์ไม่พอ ต้องให้เจ้าของร้านเพิ่มสิทธิ์ **จัดการคำสั่งซื้อ** ให้
(เจอมาแล้วกับ Lazada — บัญชีที่มีแค่สิทธิ์ *จัดการโฆษณา* เปิดหน้าคำสั่งซื้อไม่ได้)

**ดึงล้มด้วย `PARSE_ERROR` ทั้งที่หน้าเว็บปกติ**
เช็คก่อนว่ามีหน้าต่าง Chrome อื่นของโปรเจกต์เปิดค้างอยู่ไหม
การเปิดหน้าต่างล็อกอินระหว่างรอบดึงกำลังทำงานทำให้ Chrome แย่งเครื่องกัน
จน timeout 6–10 วินาทีไม่พอ แล้วล้มด้วย "หาปุ่มไม่เจอ" ทั้งที่ปุ่มอยู่ครบ
**รอให้จบทั้งรอบก่อนค่อยเปิดหน้าต่างใด ๆ** — ดูภาพหน้าจอตอนพังได้ที่ `logs/screenshots/`

**`❌ มีรอบที่กำลังรันอยู่จริง (pid ...)`**
มีรอบอื่นรันอยู่จริง ๆ — รอให้จบก่อน
ถ้าโปรเซสเจ้าของ lock **ตายไปแล้ว** (ถูกสั่งหยุด / เครื่องดับกลางรอบ) ระบบจะยึด lock
คืนให้เองทันที ไม่ต้องรอ ส่วนกรณีที่อ่าน pid ไม่ได้จะยึดคืนเมื่อ lock เก่าเกิน 6 ชม.
อยากปลดเดี๋ยวนั้น: ลบไฟล์ `data/run.lock`

**รอบโหลด Postgres ล้มด้วย exit 7**
ต่อฐานไม่ได้ — เกือบทุกครั้งคือยังไม่ได้เปิด VPN เปิดแล้วสั่งซ้ำได้เลย

**รอบโหลด Postgres ล้มด้วย exit 1 พร้อมข้อความว่าไฟล์สกรีนไม่ครบ**
ทำงานถูกต้องแล้ว — มันปฏิเสธที่จะโหลดข้อมูลไม่ครบขึ้นฐาน
ให้ไล่ดึงร้านที่ล้มให้ครบ แล้วสั่ง `screen_orders.py` ซ้ำก่อนโหลดใหม่

**ภาษาไทยใน `.ps1` เพี้ยนเป็น `เธตเธขเธง`**
ไฟล์ถูกเซฟแบบไม่มี BOM PowerShell 5.1 จะอ่านด้วยโค้ดเพจ 874 แล้ว parser พังทั้งไฟล์ ตรวจด้วย:

```powershell
[System.IO.File]::ReadAllBytes('run_daily.ps1')[0..2]
```

ต้องได้ `239 187 191` ถ้าไม่ใช่ ให้เซฟใหม่เป็น **UTF-8 with BOM**

**สคริปต์ `.ps1` ตายเงียบ ไม่มีอะไรใน log**
บน PowerShell 5.1 ถ้าตั้ง `$ErrorActionPreference = 'Stop'` แล้วเรียก `& $exe ... 2>&1`
พอโปรแกรมเขียนอะไรลง stderr **แม้แต่ข้อความเตือนธรรมดา** จะกลายเป็น `NativeCommandError`
ซึ่งเป็น terminating error สคริปต์ตายตรงนั้นก่อนได้เขียน log
ใช้ helper `RunExe` ที่มีอยู่แล้วใน `pg_daily_load.ps1` แทน

**เปิด Excel แล้ว `order_id` กลายเป็น `1.23457E+18`**
ไม่ควรเกิด — exporter บังคับ `number_format = "@"` ไว้แล้ว ถ้าเจอแปลว่ามีบั๊ก แจ้งได้เลย
